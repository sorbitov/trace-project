PROBLEM / OPPORTUNITY

(WHY HANDLE LAYER)

Wallet addresses are infrastructure.
People think in identities.

THE FRICTION

Stablecoin payments still begin by requesting, copying and checking a long wallet address. That breaks the natural flow of social payments.

THE RISK

A mistyped or substituted address can make a transfer irreversible. The sender also has no reliable proof that the address belongs to the intended social identity.

THE HANDLE LAYER MODEL

Verify the identity first, then authorize the requested action. Today that action is escrow settlement; the same boundary can support access, claims and agent permissions.

KNOWLEDGE / REFERENCES

(ANSWER-FIRST / AI-READABLE)

What the system is.
What it is not.

HandleLayer connects a verified X identity and an EVM wallet to programmable onchain actions. The first module routes private USDC escrow on Arc; it does not claim mainnet deployment or production readiness.

01What is HandleLayer?

HandleLayer is an identity routing layer that connects a verified X account and an EVM wallet to programmable onchain actions. Its first module is private USDC escrow on Arc.

02How are funds protected?

USDC is held by an Arc escrow contract. A verified recipient can claim it with a short-lived authorization, while the sender can cancel an eligible payment or refund it after expiry.

03Why require X and a wallet?

X OAuth verifies the intended social identity. A wallet signature separately proves control of the address that funds or receives the onchain action.

04Is it live on Arc mainnet?

No. The repository contains a locally tested MVP for Arc Testnet. Public contract deployment, independent security review and a production decision remain roadmap milestones.
